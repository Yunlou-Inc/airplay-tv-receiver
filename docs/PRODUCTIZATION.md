# 云楼投屏 产品化建议书

> 基于 `master` 当前代码（40 个 Kotlin 文件，commit `d97a26f4`）实测梳理。
> 目标：把「能跑的工程样机」变成「普通家庭敢装、会用、愿意推荐的产品」。

## 1. 现状判断

功能其实不缺：视频/音频/镜像三条链路、播放器控制、下载、日志、40+ 项设置都在。
问题不在功能，在**信息架构是给开发者看的，不是给用户看的**。

一句话：现在打开是「一个 AirPlay 服务端调试面板」，不是「一台电视的投屏功能」。

## 2. 五处一眼就不像产品的地方

| # | 现象 | 证据 | 用户感受 |
|---|---|---|---|
| 1 | 全英文界面 | `res/values/strings.xml` 100+ 条字符串全是英文，只有 `app_name` 是「云楼投屏」；无 `values-zh` | 中国电视用户第一眼劝退 |
| 2 | 一级 Tab 有 Logs | `MainScreen.kt:84-88`，`OVERVIEW / LOGS / SETTINGS` 平级 | 「这是给程序员用的吧」 |
| 3 | 设置项暴露内部常量 | `strings.xml` 里 `setting_enforce_sdr` 标题就是 `MediaFormat.KEY_COLOR_TRANSFER`，还有 `KEY_PRIORITY`、`KEY_OPERATING_RATE` | 看不懂，不敢动 |
| 4 | 首屏是空状态 + Cast 图标 | `OverviewContent` 只有 64dp 灰色 Cast 图标和一行 "Waiting for connection..." | 不知道该干什么 |
| 5 | 图标/banner 是灰度 Material 素材 | `drawable/banner.xml` 白底灰图标、`ic_launcher_foreground.xml` 同一图形 | TV 桌面上一排应用里像系统设置项 |

另外三个隐性硬伤：

- **没有 About 页**：无版本号、无源码链接、无 GPL-3.0 声明、无「不收集数据」说明。GPL 分发义务和用户信任同时缺位。
- **签名不固定**：CI 每次生成一次性 keystore，两个版本不能覆盖安装，升级必须先卸载，设置全丢。这是最不像产品的一点。
- **没有下载渠道**：GitHub Release 对普通用户等于不存在（要梯子、要手动开未知来源）。

## 3. 路线图

### P0：先让它「像」，1～2 天

**P0-1 中文化（收益最大，成本最低）**

- 把 `res/values/strings.xml` 改为中文，新增 `res/values-en/strings.xml` 存英文。
- 目标用户是中国电视，默认中文，英文作为 fallback。
- 100+ 条，机械但必须做。术语统一：Sender→发送端、Receiver→本机、Mirroring→屏幕镜像、PIN→配对码。

**P0-2 Tab 收敛**

- 一级只留「首页」「设置」。
- 「运行日志」移到 `设置 → 高级 → 运行日志`，或在关于页连点版本号 5 次解锁。
- `MainScreen.kt` 的 `Tab` 枚举从 3 项减到 2 项。

**P0-3 设置分层**

- 基础层（默认可见）：设备名称、开机自启、分辨率、配对码开关、允许新设备。
- 高级层（折叠）：解码器、H.265、SDR、缓冲、音频延迟。
- 开发者层（开关解锁）：现有 `KEY_*` 三项。
- **所有 `MediaFormat.KEY_*` 标题必须换成人话**，例如：
  - `KEY_COLOR_TRANSFER` → 「强制 SDR 输出」
  - `KEY_PRIORITY` → 「音频解码实时优先级」
  - `KEY_OPERATING_RATE` → 「请求最高解码帧率」

**P0-4 首屏重做**

结构建议（自上而下）：

1. 品牌区：Logo + 「云楼投屏」+ 设备名（如「客厅电视」）
2. 状态区：一个大状态点 + 一句话（未启动 / 等待连接 / 正在镜像 / 正在播放）
3. 三步指引（未连接时显示）：
   - 手机和电视连同一个 WiFi
   - iPhone 打开控制中心
   - 点「屏幕镜像」选「客厅电视」
4. 主按钮：启动 / 停止
5. 右下角：设置入口

**P0-5 About 页**

- 版本号、构建日期、commit SHA
- 源码地址（GPL-3.0 义务）
- 许可证全文入口
- 隐私说明：不收集任何数据、无遥测、无广告
- 检查更新（指向 GitHub Releases API 即可）

**P0-6 品牌视觉**

- 一套真正的图标：深色底 + 单一主色 + 可识别的「投」意象，替换现有灰度 Cast。
- TV banner 需 320×180，且要在深色桌面上可辨。
- `Theme.kt` 关闭动态取色（`dynamicLightColorScheme`），固定品牌色，避免跟着电视系统变色。

### P1：把体验做顺，约 1 周

| 项 | 内容 | 验收 |
|---|---|---|
| 首次启动引导 | 3 屏：同网要求 → 权限说明 → iOS 操作图示，可跳过 | 新装用户 30 秒内知道怎么投 |
| 连接反馈 | 显示发送端名称、分辨率、码率、延迟；断开时明确提示 | 用户知道「连上了没」 |
| 错误人话化 | native 错误码映射为可操作建议：端口占用→换端口；搜不到→检查 AP 隔离/2.4G；解码失败→切软解 | 不再只显示 "Error starting server" |
| 遥控器体验 | 方向键焦点顺序、返回键不误退出、OK 键语义一致 | 全程只用遥控器可完成 |
| 常驻体验 | 开机自启默认开、前台通知可一键停止、后台不异常耗电 | 插电即用，不用每次手动开 |
| 诊断包 | 日志导出附带设备信息（型号/Android 版本/ABI/内存） | 用户反馈问题一次说清 |

### P2：能分发，约 1 个月

1. **固定签名**：生成正式 keystore，离线保管 + CI secret。没有这一步，永远无法平滑升级。
2. **落地页**：一个静态页（GitHub Pages 即可）：下载按钮、三步图文、SHA256、FAQ、更新日志。中文域名更佳。
3. **版本策略**：`versionCode` 单调递增、`CHANGELOG.md`、应用内「有新版本」提示。
4. **真机矩阵**：至少覆盖 32 位/64 位电视各一台、Android 7/9/11 各一版、iPhone 两代。
5. **质量基线**（当前全部未测）：
   - 冷启动到可投 ≤ 3 秒
   - 投屏首帧 ≤ 2 秒
   - 音画同步偏差 ≤ 80ms
   - 连续播放 2 小时无崩溃、无内存增长
   - 断网 10 秒后自动恢复

## 4. 合规与命名边界

- 不要使用 Apple 的 AirPlay 标志、不要写「AirPlay 认证」「官方支持」。对外表述用「兼容 AirPlay 协议」。
- GPL-3.0：分发 APK 必须能获取完整对应源码。About 页放仓库链接是最低成本做法。
- 无遥测是优点，要在隐私说明里明确写出来，这是差异化。

## 5. 建议先做哪三件

如果只做三件，按这个顺序：

1. **中文化**（P0-1）——观感变化最大，风险最低。
2. **首屏 + 三步指引**（P0-4）——决定用户会不会用。
3. **设置分层 + KEY_* 改人话**（P0-3）——决定用户敢不敢动。

这三件做完，「不像产品」的评价基本会消失；剩下的签名、渠道、真机矩阵是「能不能长期用」的问题。

## 6. 需要拍板的三件事

1. 默认语言：中文优先（推荐），还是中英双语跟随系统？
2. Logs 入口：收进「设置 → 高级」，还是连点版本号解锁（更隐藏）？
3. 是否现在生成正式签名 keystore（决定后续能否平滑升级；一旦发布就不要更换）。
