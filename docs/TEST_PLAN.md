# 测试计划

## 当前状态

仓库已有 Kotlin 状态归约单元测试，以及 Rust 模块内测试和 RTSP 模糊目标骨架；但本任务没有可核验的执行结果、覆盖率或设备测试报告。以下计划不表示已经通过。测试结果须关联提交、环境和发送端版本。

## 测试层次

| 层次 | 内容 | 退出条件 |
|---|---|---|
| 单元 | 编解码、长度边界、状态迁移、超时、密钥清理、缓冲算法 | 正常/边界/错误路径覆盖；关键状态无未测迁移 |
| 属性/模糊 | 控制解析、发现记录、媒体封装、状态序列 | 持续语料运行无崩溃、越界、死锁或无限增长；缺陷转为回归样例 |
| 集成 | 发现→配对→会话→播放→停止；重连、网络切换 | 每个阶段可观测且失败清理资源 |
| 互操作 | 明确列出的发送端硬件和系统版本 | 逐组合记录通过/失败/限制；不得外推“完整兼容” |
| 性能/稳定性 | 启动、首帧、抖动、同步、长时播放、并发拒绝 | 达到本文件下述基线且无持续资源增长 |
| 安全 | 未授权、重放、降级、畸形输入、资源耗尽、秘密扫描、沙箱 | 高/严重问题为零，失败均关闭并可恢复 |

## AirPlay 接管端到端验收

“接管”定义为：经本机用户明确授权后，受支持发送端能将当前播放安全切换到电视接收器；电视呈现音视频并可停止/断开，非授权发送端不能接管。首个受支持组合必须被精确记录。

必须全部满足：
1. 设备仅在配置的本地接口被发现，名称与能力准确；停止服务后记录及时撤销。
2. 新发送端必须通过电视屏幕确认；取消、错误码、超时、重放和连续失败不能建立会话。
3. 授权会话协商后开始播放；不得明文回退；断开清除会话秘密和媒体缓冲。
4. 参考 H.264/AAC（若最终合法规范和实现选择支持）样例可播放；不支持编码明确拒绝，不崩溃或假播放。
5. 1080p30 基线目标：稳定网络下从用户确认到首帧 ≤ 5 秒；连续 30 分钟无非预期中断；音视频偏差绝对值 ≤ 100 毫秒；进程常驻内存不存在持续无界增长。该目标需在选定硬件上校准并记录测量方法。
6. 发送端主动停止、电视取消、网络中断和应用退出均在 5 秒内结束会话并回到可用状态。
7. 另一未授权发送端不能抢占；并发策略（拒绝或经用户确认切换）一致且可测试。
8. 畸形控制/媒体输入、连接洪泛和解码器崩溃不能获得主进程权限、泄露秘密或导致持久不可用。

## 配对认证单元验收

Rust `pairing` 模块回归测试覆盖：错误 PIN 不改变确认状态；并发待确认请求返回 `Busy`；未知 Apple 私有步骤返回 `UnsupportedProtocol`；短期凭据可重连且过期后拒绝；撤销后拒绝且覆盖凭据；重复序列、窗口外旧序列、跨会话序列均拒绝；并发会话防重放状态相互隔离。真实适配还必须增加 Keystore 不可导出性、认证标签失败不推进窗口、随机源失败、进程重启和并发网络压力测试。

## 测试数据规则

仅使用自有或授权媒体与设备。抓包先脱敏；不得保存真实配对秘密。随机生成或合成畸形语料。失败报告包含提交、环境、步骤、预期/实际、日志摘要，不含秘密。

## 媒体骨架单元测试增量

`MediaPipelineTest` 在纯 JVM 验证：队列单元/字节上限与背压、超时空轮询、flush/close 释放；H.264 NAL 上限及 SPS/PPS 类型拒绝；平台适配器非法迁移、正常启动/停止和幂等 release。后续设备测试须以合成或授权数据覆盖真实 `MediaCodec` 输入缓冲超时、`AudioTrack` 短写、解码错误、Surface 丢失和并发 teardown；当前测试不构成可播放或 AirPlay 兼容证据。
