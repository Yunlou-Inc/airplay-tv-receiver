# 目标 L3「能真投屏出画面」：所需前置清单

> 背景：验收方要求能力等级 ④（能真投屏出画面，见 `DEFINITION_OF_DONE.md` 的 L3）。
> 本文正面回答"实现 L3 需要什么"，并把需求分成三类：
> **A. 可先行落地（纯工程，不依赖任何外部资料/设备）** — 本轮已开工；
> **B. 硬门禁（缺了就法律/技术上不可能）** — 必须由需求方提供或决策；
> **C. 外部条件（需要设备、真机、可信构建环境）** — 需要资源投入。
>
> 纪律：本项目不宣称 Apple 认证或完整兼容；未测组合一律标"未知"。配对/认证密码学
> 只能基于合法、可审查的协议资料，禁止猜测或逆向私有算法（见 `THREAT_MODEL.md` / `SECURITY.md`）。

---

## A. 可先行落地（纯工程，已开工，无需外部输入）

这部分无论资料/设备是否到位都必须做，是 L3 的地基。本轮已提交代码增量：

| 项 | 状态 | 说明 |
|---|---|---|
| FFI 监听接口 `listen_start/stop/state/bound_addr` | ✅ 本轮新增 | 复用 `frontend.rs` 有界 TCP 服务端；显式授权门禁（authorized=1）、通配地址拒绝、回环绑定、实际端口回读；含单测 |
| Kotlin/JNI 接线 | ✅ 本轮新增 | `AirPlayProtocol` 门面 + JNI 桥接暴露监听接口，native 缺失时仍优雅降级 |
| M1-2 授权门禁 + 显式绑定设计 | ✅ 已推送 | `docs/M1-2-android-integration-design.md` |
| 媒体骨架（背压队列/H264 约束/状态模型） | ✅ 已有 | `media/`，纯 JVM 模型，无真实解码 |

**仍需的信封环境步骤**（沙盒无法构建，见 `DEV_ENV_AND_RUNBOOK.md`）：cargo-ndk 编译三 ABI `.so`、Gradle 接入 jniLibs、单测/真机跑通。

---

## B. 硬门禁（无可替代，必须由需求方/维护者解决）

这是 L3 能否成立的**决定性前置**——不是排期问题，工程无法绕过。

### B1. 合法、可审查的 AirPlay 配对/认证协议资料 ⚠️ 最大门禁
- **为什么必需**：真投屏的第一步是发送端与接收端配对认证、建立加密会话。当前 `pairing.rs`
  的私有密码学部分是 `UnsupportedAirPlayProtocol`（明确拒绝态），因为没有合法资料来源。
- **红线**：项目明确不猜测、不逆向 Apple 私有算法，不提供设备唯一私钥，不规避 DRM。
  没有合法资料，配对永远停在拒绝态 → **L3 无法达成**。
- **需要需求方回答**：
  1. 是否已取得可合法使用、可审查的 AirPlay 协议/配对规范资料？来源是什么？
  2. 是否接受"仅支持公开标准子集"的降级路径（例如只用 RTSP 控制面 + 明文/本地测试流，
     不做真实 AirPlay 配对）？这实际上是 L1+，不是真投屏。
  3. 目标 iOS / macOS 版本，以及使用的"发送端"具体是什么（真机 iPhone？第三方 App？）。
- **决策后果**：资料到位 → 启动 Milestone 3；资料不到位 → 项目能力天花板为 L1，L2/L3 不可承诺。

### B2. 仓库级许可证选型（法律决策）
- Rust crate 声明 `MIT OR Apache-2.0`，仓库级 `LICENSE` 仍是"不授予权利"占位符，内部冲突。
- 需维护者选定并统一，否则代码无法合法分发/商用。

### B3. 目标组合的明确与授权
- `MILESTONES.md` 要求先锁定**首个发送端/接收端组合**（哪款 iPhone/iOS + 哪台 Android TV/电视）。
- 需要有权使用的设备、媒体与密钥；测试抓包脱敏，不保存真实配对秘密。

## C. 外部条件（资源投入，非技术不可能）

| 项 | 用途 | 说明 |
|---|---|---|
| Android TV 真机（接收端） | 运行 App、验证发现/监听/播放 | 模拟器不足以验证 DNS-SD 与媒体输出 |
| iPhone/iPad（发送端）+ 受控局域网 | 真实互操作 | 与接收端同网段、无隔离 |
| 可信构建环境（JDK17 + SDK35 + NDK + cargo-ndk + 网络） | 编译三 ABI `.so` 与 APK | 当前沙盒缺 SDK/NDK，网络不稳；或改用 CI 出包 |
| 参考媒体（如授权 H.264/AAC 片段） | 30 分钟连续音频 / 1080p30 视频基线验收 | 需有权使用 |
| 签名密钥 | 发布候选产物签名 | Milestone 9 |

## 结论与各等级可达性

| 等级 | 是否可达 | 前置 |
|---|---|---|
| L0 骨架演示 | ✅ 已具备 | — |
| L1 安全监听 | ✅ 工程可进行 | 本轮代码增量 + 可信环境构建验证 |
| L2 配对授权 | ⚠️ 卡 B1 | **合法协议资料到位**（硬门禁） |
| L3 真投屏出画面 | ⚠️ 卡 B1+B3+C | B1 资料 + B3 目标组合 + C 真机/媒体/构建 |
| Apple 认证/完整兼容 | ❌ 不承诺 | 项目立场明确排除 |

**一句话**：工程侧（A）我可以继续推进到"能安全监听、能看到请求进来"；但从 L2 起的
**配对、解密、真投屏**，卡在 **B1 合法协议资料**——这是需要需求方先回答的问题，
不是我写代码能解决的。请优先回答 B1 的三个子问题，我再据此决定能否启动 Milestone 3。
