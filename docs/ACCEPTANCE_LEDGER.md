## 3. 架构决策记录（ADR）补录

### ADR-001：Android 与 Rust 在完成 FFI 评审前保持独立

- 状态：已接受（反映当前实现）
- 背景：Rust 协议层存在，但没有 Android 构建集成；过早耦合会掩盖 ABI、内存所有权和错误边界风险。
- 决策：在 ABI 矩阵、所有权规则、错误映射、线程模型及集成测试获评审前，Android 不宣称使用 Rust 协议层。
- 后果：可分别验证；暂不能声称端到端接收能力。
- 证据：`BUILDING.md`、`README.md`、`docs/ARCHITECTURE.md`。

### ADR-002：发现功能默认关闭且采用保守能力声明

- 状态：已接受（反映当前实现）
- 背景：仅有 DNS-SD 发布接缝，没有协议监听和完整互操作能力。
- 决策：`DiscoveryConfig.enabled` 默认关闭；Android 13+ 经用户明确启用后才申请附近 Wi-Fi 权限；能力默认 `features=0x0`，不得夸大兼容性。
- 后果：降低误暴露与误宣传风险；启用前需要权限和真机验证。
- 证据：`docs/ARCHITECTURE.md`、`BUILDING.md`、`app/src/main/java/com/example/airplaytv/discovery/`。

### ADR-003：归档必须绑定干净 Git 提交

- 状态：已接受（由脚本实施）
- 背景：目录打包无法证明源码来源及排除本地产物/秘密。
- 决策：只允许在干净工作树使用 `git archive`，以提交日期和提交短标识命名，并生成 SHA-256。
- 后果：当前无 Git 元数据的交付目录不能完成正式归档。
- 证据：`scripts/source-archive.sh`、`BUILDING.md`。

- 观察端：同一局域网内 1 台笔记本或手机，运行 DNS-SD 浏览工具；记录工具名称及版本。
- 网络：隔离测试局域网，接收端与观察端同一二层网络；禁止公网端口映射；记录路由/AP 型号、固件、SSID、频段、客户端隔离/组播过滤设置、IP/掩码；另准备可控断网与 Wi-Fi 重连条件。

### 7.3 执行步骤

1. **默认关闭**：首次启动，不启用发现；观察端确认无该设备 `_airplay._tcp.`/`_raop._tcp.` 记录。
2. **拒绝权限**（Android 13+）：请求启用后拒绝；确认不发布，并记录界面/状态/日志。
3. **允许并启用**：授予权限、启用发现；确认两类记录出现，名称、端口、型号、版本、能力字段与配置一致，且不得把记录出现写成 AirPlay 兼容通过。
4. **停止/撤销**：关闭发现或停止服务；确认记录及时撤销，记录耗时。
5. **断网/重连**：启用状态下断开网络，确认撤销/错误状态；重连同一网络，确认重新发布，记录耗时。
6. **名称冲突**：在观察端发布同名记录，确认平台改名/冲突事件可观察，应用不崩溃。
7. **重复循环**：启用/停用和断网/重连各 20 次，记录泄漏、重复记录、崩溃或无法恢复。
8. **安全边界**：确认应用服务仍不可从外部应用直接绑定/启动；确认未打开声明端口监听（按当前设计）。
9. 导出脱敏日志、DNS-SD 观察结果和必要截图；计算文件摘要，关联提交与 APK。
