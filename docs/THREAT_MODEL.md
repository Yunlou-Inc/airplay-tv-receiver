# 威胁模型

## 范围与假设

目标是同一局域网内的电视接收器。攻击者可加入或影响局域网、发送任意协议字节、伪造发现信息、反复连接并提供恶意媒体；还可能读取普通文件或诱导用户配对。不假设局域网可信。当前没有实现可供安全验证。

## 资产

- 长期设备身份、配对资料和会话密钥
- 用户授权意图、电视控制权与可用性
- 音视频内容、元数据和观看隐私
- 进程完整性、系统权限和更新链
- 日志、崩溃转储与兼容性抓包

## 威胁与措施

| 威胁 | 影响 | 必需控制 | 验证方式 |
|---|---|---|---|
| 未授权接管/配对诱骗 | 播放或控制电视 | 屏幕确认、短时配对窗口、明确发送端身份、撤销入口、失败退避 | 未确认不可建会话；重放/暴力尝试被拒绝 |
| 中间人、降级、重放 | 会话劫持/泄露 | 经审查的认证密钥交换、能力绑定、随机数/序列号、拒绝降级 | 篡改、旧消息和降级组合测试失败关闭 |
| 解析器内存破坏 | 代码执行 | 内存安全语言优先、长度上限、整数检查、模糊测试、沙箱 | 消毒器/模糊测试无崩溃或越界 |
| 恶意媒体攻击解码器 | 代码执行/逃逸 | 成熟解码库、独立低权限进程、系统调用/文件/网络限制 | 畸形语料、沙箱逃逸回归测试 |
| 资源耗尽 | 卡死/重启 | 连接、帧、缓冲、CPU/内存上限；超时与速率限制 | 压力下保持可控制并回收资源 |
| 密钥/隐私泄露 | 长期冒充/隐私损失 | 安全存储、最短保留、日志脱敏、转储过滤 | 秘密扫描与日志断言 |
| 发现欺骗 | 连错目标/信息泄露 | 最少广播信息、配对时绑定屏幕身份、接口范围控制 | 伪造记录不能绕过用户确认 |
| 更新/依赖投毒 | 持久控制 | 锁定依赖、摘要/签名、物料清单、可回滚签名更新 | 篡改产物拒绝安装 |

## 配对认证边界（已实现框架）

- Rust `pairing` 模块只实现厂商中立的授权状态、短期凭据、会话隔离与 64 项滑动防重放窗口；它**不**声称实现 Apple 私有配对密码学。
- `PairingProtocol` 是真实 AirPlay 适配边界；在获得合法、可审查的协议资料前使用 `UnsupportedAirPlayProtocol`，并返回明确的 `UnsupportedProtocol`，禁止猜测算法或明文降级。
- `DeviceIdentity` 只暴露公有标识和不可导出的签名操作。测试使用明确标注为非密码安全的 `InMemoryIdentity`；生产必须实现 Android Keystore 适配，私钥不得进入 Rust 堆、日志或备份。
- 用户确认前不能验证配对证明；同时只允许一个待确认请求。请求和凭据均有绝对过期时间，撤销时覆盖内存凭据。
- 防重放检查必须位于消息认证成功之后，且以随机会话 ID 分区；跨会话序列、重复序列和窗口外旧序列均拒绝。会话 ID 的生产随机源和认证标签校验由网络/密码适配层负责。
- 当前内存授权表不提供持久化；进程重启后授权丢失是安全关闭行为。若以后持久化，仅可保存经 Keystore 封装且带版本/过期/撤销元数据的记录。

## 安全失败原则

认证、授权、密码学、解析或资源检查失败时必须停止会话并清理密钥；不得自动回落到明文或匿名模式。错误反馈不泄露密钥材料或可用于枚举的细节。

## 残余风险与待决项

协议资料合法来源、目标系统安全存储/沙箱能力、发送端兼容矩阵、密码套件和更新机制尚未确定。确定技术栈后必须重新进行数据流审查和渗透测试。本模型不构成生产安全认证。
