# 「完成」标准对齐清单（Definition of Done）

> 用途：用于与验收方/需求方对齐"这个项目做到什么程度才算完成"。
> 背景：验收方反馈"没完成，没必要验证"。经核实，双方对"完成"的定义并未对齐——
> 当前仓库是**安全骨架**（有界面 + DNS-SD 发现，无真实投屏），用"能投屏"的标准看自然是"没完成"。
> 本清单把"完成"拆成可勾选的能力等级，先选定目标等级，再谈验证与排期。

---

## 一、请先回答这 5 个问题

1. **你看重的是"验收演示"还是"真能投屏的产品"？**
   - 只要看到东西跑起来 → 大概率停在 L0/L1，无需法律资料。
   - 要真能投屏 → 必须经过 L2 配对，而 L2 卡在合法协议资料（见下）。

2. **下面 L0–L4，哪一级就算"完成"？（勾选一级）**

3. **若选 L2 及以上：能否提供"合法、可审查的 AirPlay 配对/认证协议资料"？**
   - 这是**硬门禁**，不是排期问题。项目自身红线：不得猜测或逆向 Apple 私有算法。
   - 拿不到 → L2 及以上**无法启动**，只能维持 `UnsupportedAirPlayProtocol` 拒绝态。

4. **首个"发送端 + 接收端"组合是什么？**（例：哪款 iPhone/iOS + 哪款 Android TV/电视）
   - 没有明确的首组合，就无法做真机互操作验证，也就无法判定"完成"。

5. **这台 macOS 10.15 机器在你流程里扮演什么角色？**
   - 只验收 → 用云端 CI 出 APK，机器零环境要求（见 `CI_APK_DELIVERY.md`）。
   - 要开发 → 这台机器带不动项目工具链（需 AGP 8.7.3 / API 35），必须先换机器或走命令行。

## 二、能力等级表（勾选你要的那一级）

| 级别 | 名称 | 跑起来能看到/做什么 | 前置条件 | 工作量性质 | 对应里程碑 |
|---|---|---|---|---|---|
| **L0** | 骨架演示（**当前状态**） | 界面 + DNS-SD 发现开关；**不能投屏**；`isAvailable=false` 是预期降级 | 无 | 已完成，无需再做 | Phase F / M0 |
| **L1** | 安全监听骨架 | 用户授权后监听本地端口；抓包/日志能看到 RTSP 请求被正确解析与拒绝；无公网暴露 | 仅工程：JNI 接线、补 `ffi.rs` 的 listen/accept、授权门禁 | 纯工程，无法律前置 | M1–2 |
| **L2** | 配对授权 | 设备完成配对、建立受保护会话 | **合法协议资料到位**（硬门禁）+ Keystore 适配 | 取决于资料；拿不到即停 | M3 |
| **L3** | 收流与播放 | 在 L2 之上接收音视频、解码、同步，电视出画面/声音 | L2 + 媒体管线 + 30 分钟稳定性 + 恶意媒体测试 | 工程 + 真机矩阵 | M4–7 |
| **L4** | 完整兼容 / Apple 认证 | — | — | **不承诺**：项目明确不宣称完整兼容或 Apple 认证 | M8–9+ |

> 关键分水岭在 **L2**：真投屏（L3）在依赖顺序上必须经过配对这一关，而配对卡在"合法协议资料"。
> 若资料无法取得，则能力天花板就是 **L1**（能安全监听、能解析请求，但不能配对、不能投屏）。
> 这不是工程排期能绕过的问题——绕过就意味着猜测/逆向私有算法，触碰项目红线。

## 三、选择 → 路线映射

| 对方勾选 | 结论 | 下一步 |
|---|---|---|
| L0 或"只要演示" | 现状已满足 | 走云端出包验收（`CI_APK_DELIVERY.md`）；先让对方知道只有界面+发现 |
| L1 | 纯工程，可做 | 按 `ADR-001` + `M1-2-android-integration-design.md` 落地接线；无需法律资料 |
| L2 | 硬门禁 | 先确认能否提供合法协议资料；不能则明确告知项目止于 L1，不猜测 |
| L3 | 大工程 + 门禁 | 需 L2 资料 + 明确首组合 + 真机矩阵；先做资料可行性评估 |
| L4 | 不承诺 | 明确说明项目不宣称完整兼容/Apple 认证，管理预期 |

## 四、一句话转述版（可直接复制给对方）

> 目前仓库是一个**安全骨架**：能看到界面和发现开关，但不能投屏——所以用"能投屏"的标准看确实"没完成"。
> 为了不再做偏，请先告诉我们：**你要做到哪一级算完成**——① 只要界面演示（现状已有）；② 能安全监听、能看到请求进来（纯工程，可做）；③ 能配对（**必须有合法协议资料，否则做不了**）；④ 能真投屏出画面（需 ③ + 媒体管线 + 真机）。
> 另外请给一个**首组合**（哪款手机投、哪款电视收），并说明这台 macOS 10.15 机器是只用来验收（那我们用云端出包，你零环境）还是要继续开发（那台机器带不动，需换机）。
