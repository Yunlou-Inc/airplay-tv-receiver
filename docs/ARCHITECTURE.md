# 架构说明

## 架构状态

本文件同时记录现状与目标设计。现有实现仅包含 Android TV Compose 界面/状态模型、一个私有服务接缝，以及尚未接入应用的 Rust 防御性协议原语（有界 RTSP 解析、发现/设备模型、会话状态机）。真实网络、配对认证、密码学和媒体管线均未实现；实现偏差必须通过架构决策记录说明。

## 目标数据流

```text
受支持发送端
  │ 发现/配对/控制/加密媒体（不可信网络）
  ▼
[网络入口与速率限制]
  ▼
[协议解析器] ──► [认证、配对与会话状态机] ──► [密钥库/平台安全存储]
  │                         │
  ├──► [媒体接收与抖动缓冲] └──► [控制与生命周期]
  ▼
[解密边界] → [受限解码进程] → [音视频同步] → [平台渲染输出]
  │
  └── 最小化遥测（不含秘密或媒体）
```

## 组件职责

| 组件 | 目标职责 | 当前状态 |
|---|---|---|
| Android TV 外壳 | 展示等待、配对、播放状态与设置 | 骨架已实现；仅内存界面状态，不代表协议事件 |
| 私有服务接缝 | 管理发现生命周期；未来高风险接收逻辑仍须另行隔离 | Manifest、本地 Binder 和 DNS-SD 生命周期已实现；无协议监听 |
| 发现服务 | 在本地网络声明能力、撤销声明 | Android DNS-SD 最小发布与网络变化处理已实现；尚未设备验证或接入真实协议监听 |
| 网络入口 | 连接上限、超时、速率限制、接口绑定 | 未实现 |
| 协议解析器 | 严格解析控制消息，拒绝歧义/超限输入 | Rust 有界 RTSP 请求解析原语；未接入网络/Android，非完整控制面 |
| 配对/会话状态机 | 身份确认、授权、重放防护、密钥生命周期 | Rust 已有厂商中立配对框架、内存测试身份、短期凭据及滑动防重放窗口；Apple 私有密码步骤明确为 Unsupported，Android Keystore 和 Router/网络接入待实现 |
| 媒体管线 | 接收、缓冲、解密、解码、同步、渲染 | 未实现 |
| 平台适配 | 音视频输出、安全存储、网络变化、电源管理 | 未实现 |
| 可观测性 | 脱敏指标、审计事件、崩溃信息 | 未实现 |

## 信任边界与不变量

- 网络数据、发现记录、媒体帧和发送端声明均不可信；每层重新验证长度、类型和状态。
- 只有认证且获本机用户授权的会话可进入媒体管线；断开后立即清除会话密钥和缓冲。
- 解码器按高风险组件隔离，采用最小权限、资源配额和沙箱；崩溃不得暴露主进程或持久密钥。
- 长期密钥只驻留平台安全存储；禁止硬编码、导出到日志或崩溃转储。
- 默认仅绑定明确选择的本地接口；不提供公网监听或远程管理。

## 生命周期

建议状态：`Idle → Discoverable → Pairing → Authorized → Negotiating → Streaming → Stopping → Idle`。任何语法错误、认证失败、超时、网络切换或资源超限都进入安全停止；禁止跳过授权直接协商媒体。

## 范围外

中继/代理、公网穿透、云端账户、录制媒体、规避数字版权管理、复制厂商设备凭据、未经证据支持的全版本兼容均不在当前范围。

## Android DNS-SD 发现（增量实现）

`NsdDiscoveryController` 通过平台 `NsdManager` 发布最小 `_airplay._tcp.` 与 `_raop._tcp.` 记录，监听默认网络变化并撤销/重发记录。`DiscoveryConfig.enabled` 默认为 `false`；能力位、端口、型号和版本均显式配置，默认 `features=0x0`，不暗示实际协议能力。平台自动改名会产生冲突事件，注册/撤销错误和网络不可用也会转为 `DiscoveryEvent`，再由现有 reducer 接入 `ReceiverUiState.discovery`。

服务仍为 `exported=false`；发现发布不会开启声明端口的监听器。Android 13+ 的 `NEARBY_WIFI_DEVICES` 必须由界面在用户明确启用发现时动态申请，拒绝时不得启动。当前实现只是 DNS-SD 发布和状态接缝，不是可连接的 AirPlay 接收端，也未验证真实 AirPlay 兼容性。

## 有界媒体管线骨架

`media` 包定义视频/音频格式、微秒时间戳、访问单元和可关闭共享缓冲边界。`H264Validator` 对 NAL、SPS/PPS、分辨率和帧率实施可配置上限；`BoundedMediaQueue` 同时限制单元数与字节数，以 `FULL` 显式背压，支持有界等待、flush 和 close 时清零释放。`MediaCodecAdapter` 与 `AudioTrackAdapter` 是 Android 平台接缝，使用严格的 `NEW → CONFIGURED → STARTED → STOPPED → RELEASED` 生命周期。当前只有可测试的纯 JVM 模型和抽象适配器，未接入 Android 解码/输出，也没有实现 AirPlay 解密或真实镜像播放。
